01 / PIPELINE

검출

파이프라인 FPS

YOLO26n FP16 · 640 / RF-DETR FP32 · 512 / DEIMv2 FP32 · 640
같은 ByteTrack·집계 규칙을 사용합니다. 정밀도와 입력 크기가 달라 모델 구조만의 효과로 해석하지 않습니다.

포함읽기 · 검출 · 추적 · 집계 · 로그제외모델 초기화 · 5회 워밍업 · 렌더 · 영상 저장

FPS는 반복 실행의 중앙값입니다. 이전 ‘검증 결과’의 24.08 FPS는 렌더·저장과 첫 워밍업을 포함해 측정 범위가 다릅니다. 촬영→표시 지연은 측정하지 않았습니다.

사용 중인 PC에서 GPU를 순차 실행했습니다. 전용 격리 벤치마크가 아니므로 반복별 변동을 함께 공개합니다.

모델영상입력IN / OUTFPS구간±0.5sIDVRAM기록
측정 기록 준비 중

VRAM은 PyTorch 모델의 peak MiB입니다. 전체 장치 사용량이 아니며, 캐시 추적 표에는 ONNX Runtime 메모리를 누락할 수 있는 수치를 표시하지 않습니다.

03 / SCOPE

범위

AI 시각 검수

AI 생성 원본 2개 · 원본만 본 AI 시각 검수 14건. 같은 클립의 시간·방향을 일대일로 대응합니다. 인물 ID가 맞는지 자동 검증한 결과는 아닙니다.

  • 구간: 원본 검수의 엄격한 시간 구간. ±0.5s: 허용 시간을 넓힌 별도 분석.
  • ‘미대응 예측 / 검수’는 이 대응 규칙에서 남은 이벤트입니다. 사람 합의 정답이나 현장 정확도로 해석하지 않습니다.
  • 추적 ID 개수는 고유 인원수가 아닙니다. 초기 재실 인원은 미정이며 IDF1·HOTA·전체 검출 누락률은 평가하지 않았습니다.
논문 ↗
국소 검토
  • F0 · 화면 밖으로 잘린 인물 주변: YOLO 0개 / RF-DETR 2개 / DEIMv2 3개 박스. 박스 수는 인원수가 아닙니다.
  • F291 · 코트 인물에 세 검출기 모두 겹친 박스 2개가 관찰됩니다.
  • ID · 코트 인물의 ByteTrack ID는 16→35로 바뀌고, TrackTrack은 12로 돌아옵니다. F291–293에서는 TrackTrack ID가 미확정입니다.
  • ReID · 두 클립 602프레임의 TrackTrack ON/OFF ID 기록은 같습니다. 이 표본에서는 ID 변화 없이 처리 비용이 늘었습니다.

선택한 장면의 관찰입니다. 위 표의 시간·방향 대응과 별개이며, 전체 검출·인물 ID 정확도를 측정한 결과는 아닙니다.
